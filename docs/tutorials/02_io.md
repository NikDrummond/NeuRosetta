# Reading and Writing Neuron Files.

NeuRosetta currently reads and writes three main formats:

| Format | Functions | Typical use |
|--------|-----------|-------------|
| **SWC** | `import_swc`, `export_swc` | Standard morphology exchange |
| **NR** | `save`, `load` | Native graph-tool based `.nr` files |
| **Mesh** | `import_mesh`, `export_mesh` | Neuron / neuropil surfaces via vedo (Developmental) |

Sample SWC files ship with the docs in `docs/data/`. `1.swc` and `2.swc` are
optic-lobe neurons from the [FAFB-FlyWire](https://codex.flywire.ai/?dataset=fafb)
dataset {ref}`[1] <ref1>`, {ref}`[2] <ref2>`, {ref}`[3] <ref3>`: segment
`720575940599457990` (T4b) and `720575940596125868` (T5c). They are renamed
`1.swc` and `2.swc` for the tutorials, so `import_swc` assigns tree IDs `1`
and `2` (the original segment IDs remain in the SWC headers).

In order to access these data, get the path from the repository root:

```python
from pathlib import Path
import neurosetta as nr

DATA = Path("docs/data")
```

---

## Import `.swc` File(s)

As is standard when using the FlyWire or other similar datasets, SWC file stems must be **integer IDs** (for example `1.swc` → tree ID `1`). The file name is *assumed* to be the neuron ID in the dataset it comes from!

You can import a single `.swc` file as follows:

```python
tree = nr.import_swc(DATA / "1.swc")
print(tree)
```

This will return a single Tree object, our class for handling neurons. Have a look {doc}`here <03_tree_basics>` for more information on the class.

For multiple `.swc` files, you can pass a directory, which returns a {class}`~neurosetta.api.Forest`, and you can find more information about forests {doc}`here <06_forests>`:

```python
forest = nr.import_swc(DATA)
print(forest)
```

You additionally have the arguments `parallel`(bool, default = False) and `max_workers`(int, default = None) for multithreaded parallel imports of `.swc` files. You additionally have `progress`(bool, default = False) for a progress bar.  

```{note}
When you import an `.swc` file, the default empty metadata is used which is as follows:


| Key | Value |
|--------|-----------|
| 'units'| Assumed to be 'dimensionless' at import, unless specified |
| 'file_path'| The location of the `.swc` file|
| 'isReduced'| This is a bool flag, explained in {doc}`04_tree_surgery`|

The metadata dictionary can have whatever information you want, and is useful for a number of reasons, but it will not be preserved (currently) when a neuron is exported as an `.swc`. It is however when the `.nr` file type is used.
```

## Export `.swc` File(s)

NeuRosetta is generally built so that users can either call a function on an existing tree or forest, or call things on the tree or forest object itself. For exporting a single {class}`~neurosetta.api.Tree`, this works as follows:

```python
from pathlib import Path
import tempfile

out = Path(tempfile.mkdtemp())
nr.export_swc(tree, out)
# or:
tree.export_to_swc(out)
```
(note-export-filename)=
````{note}
In the above example, `out` is a directory. As in this example, NeuRosetta will use the neuron ID as the file name by default. If, however, you provide a file name like so:

```python
tree.export_to_swc(out / "3.swc")
```

Then the `.swc` file will be saved with the updated file name. However, because we assume the file name is **also** the neuron ID within the dataset, you may lose this information by changing the file name, so be careful.
````

For a forest, the process is practically identical, except you *must* pass a directory:

```python
nr.export_swc(forest, out)
# or
forest.export_forest_to_swc(out)
```
As with importing multiple `.swc` files, you have the same three `parallel`,`max_workers`, and `progress` options.

````{note}
When importing neurons, we assume by default that their spatial units are not known, so are noted as 'dimensionless' within the metadata. However, using the `set_units` argument, for example:

```python
tree = nr.import_swc(DATA / "1.swc", set_units = 'nm')
```

Will specify that the neuron is in nanometer units at import.
````

## Native `.nr` files

`.nr` files store graph-tool graphs, wrapping the `.gt` file format. You can read about it in detail [here](https://graph-tool.skewed.de/static/docs/stable/gt_format.html). NeuRosetta generally prefers working with the `.nr` file type, and it has one key advantage - "Bound" attributes can always be saved with the graph. This includes any modifications made to the metadata of a neuron, for example.

```python
nr.save(tree, out)
# or:
tree.save_tree(out)

reloaded = nr.load(out)
print(reloaded)
```

Saving a forest writes one `.nr` file per tree ID into a directory:

```python
nr.save(forest, out)
forest2 = nr.load(out)
print(forest2.ids())
```
See the above note on {ref}`filenames <note-export-filename>` however, as the same rule applies. 

## Import Mesh Files (Developmental)

Meshes are loaded through [vedo](https://vedo.embl.es/). Choose the object type with `mesh_type`:

```python
# neuron surface → Tree_mesh / Forest_mesh
# neuron_mesh = nr.import_mesh("neuron.ply", mesh_type="Neuron")

# neuropil surface → Neuropil / Neuropils
# neuropil = nr.import_mesh("neuropil.ply", mesh_type="Neuropil")

# nr.export_mesh(neuropil, "out/neuropil.ply")
```

Default export format is **binary PLY** (`.ply`). Other formats supported by
vedo (OBJ, STL, VTK, …) can be selected via the output path / `fileoutput`
argument.


## What to remember

- SWC stems must parse as integers.
- File → single object; directory → collection (`Forest` / `Forest_mesh` /
  `Neuropils`).
- Prefer `.nr` for NeuRosetta-native workflows; use SWC for interoperability.
